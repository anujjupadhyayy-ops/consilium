# P3.6 — Rules trigger agents (replaces LLM routing)

Status: IMPLEMENTED on branch `p3.6-rules-trigger` (owner checks in §8.6 outstanding -- see `docs/P3.6-BUILD-REPORT.md`). Supersedes `P3.6-Relevance-Fanout-Spec.SUPERSEDED.md` (do not implement that file).
Branch: `p3.6-rules-trigger`. Scope is frozen to this document; new ideas go to a separate backlog.

---

## 1. Why (the bug)
- A single LLM routing call (`route_node` / `_llm_route`) decided which agents ran. When it skipped an agent,
  that agent's rules never ran, so its code-enforced blocker could not fire.
- Observed: `supplier_milestone` seed (Operations `licence_provisioned_for_new_date: false`) returned
  "Approve, conditional on Gate 2" on a run where Operations was skipped, and "Decline" on others.
  Same input, opposite verdicts. An LLM held a veto over a rule meant to be law.
- The routing prompt also instructs the model to "make a clearly reasonable illustrative estimate" for
  unstated figures, so free-text verdicts can rest on invented numbers.

## 2. Principle
**Rules decide. The LLM reads and explains.**
Every agent checks its rules on every decision. An agent is *triggered* if any of its rules fires on stated
facts. The Chief of Staff (LLM) summarises the triggered risks; the verdict direction is set in code.

## 3. Flow
```
message/seed ─► facts (seed: authored | free text: extracted with verified quotes, never estimated)
             ─► EVERY agent checks its rules (no router; nothing can be skipped)
                  any rule fires       → TRIGGERED: stance, rule(s) fired, evidence
                  no rule fires        → NOT TRIGGERED, plus "Couldn't check: <fields not stated>"
                  keyword mentioned but field not extracted → "Unclear: <field>" (tripwire)
             ─► verdict direction (code): blocker wins; unchecked/unclear blocker field caps the verdict
             ─► Chief of Staff (LLM): summary of risks, why the brief is a challenge, conflicts
```

## 4. Definitions
- **Stated fact**: a seed-authored value, OR an extracted value with ≥1 verbatim evidence quote verified in code.
  Nothing else. No schema defaults, no estimates.
- **Rule**: `{id, description, fields, when, stance, keywords?}` — `when` is an expression over stated fields
  and (optionally) config thresholds; `stance` ∈ `yes | conditional | no | blocker`.
- **Rule fires**: every field in `fields` is stated AND `when` evaluates true. A rule with an unstated field
  never fires and never errors; it is reported as "couldn't check".
- **Derived values** (e.g. CPI, SPI, forecast utilisation): computed in code only when all inputs are stated;
  otherwise the derived value is not stated.
- **Agent stance when triggered**: the most severe stance among its fired rules
  (`blocker > no > conditional > yes`). All fired rules are listed.
- **Blocker field**: any field referenced by a rule whose stance is `blocker`.

## 5. Components

### 5.1 Rules engine (`backend/agents/rules.py`, new)
- Safe expression evaluator: `ast.parse(mode="eval")`, whitelist only `BoolOp(and/or)`, `UnaryOp(not)`,
  `Compare(>,>=,<,<=,==,!=)`, `Name`, `Constant`. Names resolve to stated facts, then derived values, then
  config scalar thresholds. Anything else rejected at config load. No `eval`/`exec`.
- `check_rules(agent, facts) -> {fired: [...], unchecked: [field...], stance | None}`.

### 5.2 Agent configs (`backend/agents/configs/*.json`)
- Each agent's existing `evaluate()` logic is re-expressed as `rules[]`. Thresholds stay as config scalars
  (still editable in the Council UI). Rule `when`/`fields`/`stance` are system-governed: the Council UI and
  config-save endpoint cannot add/remove/alter rules whose stance is `blocker`.
- `keywords` required on every blocker rule (tripwire, §5.5).
- `registry.py` validates rules at load and on save with readable errors.

### 5.3 Migration method (regression control — mandatory)
1. **Before any logic change**, commit golden baselines produced by the CURRENT code:
   - `tests/golden/seed_supplier_milestone.json`: every agent's stance + driving constraint.
   - `tests/golden/factsets_<agent>.json`: ≥200 generated COMPLETE fact sets per agent, including values at,
     just below and just above every threshold, and every boolean combination that matters; with the current
     `evaluate()` output for each.
2. Migrate one agent at a time: Finance → PMO → Operations → Delivery.
3. Keep the old `evaluate()` as a reference oracle during migration. Differential test: old vs new stance and
   driving constraint on every golden fact set. Zero differences, or each difference listed in
   `docs/P3.6-migration-diffs.md` with reason and marked "approved by owner" — never silently accepted.
4. Equivalence for the differential test (so intended improvements aren't logged as hundreds of diffs):
   stance must match exactly, where old `yes` ≡ new not-triggered-with-no-unchecked-fields (unless a new `yes` rule
   fires, then new stance `yes`); old driving constraint must be one of the new fired rules' constraints (new may list
   more). Anything else is a difference to log.
5. Compare COMPLETE fact sets only (old code used defaults for gaps, so its partial-fact output is not a valid oracle).
6. Delete old `evaluate()` only when all four agents are at zero unapproved differences. Golden tests stay permanently.

### 5.4 Extraction (free text only; seeds bypass)
- One LLM call per agent, parallel, that agent's facts fields only, temperature=0.
- Whole message to every agent; never chunked. If message exceeds `MODEL_CONTEXT_TOKENS` (config, conservative
  default, documented in README), fail with a clear error; never truncate.
- Prompt: return null for anything not stated; no estimates; each value must include `evidence` (verbatim quotes,
  may span paragraphs). Remove the "illustrative estimate" instruction everywhere.
- Code verifies each quote is a substring of the message after whitespace normalisation. Missing/unverifiable
  evidence or wrong type → value discarded → field not stated.
- Persona text must NOT appear in extraction prompts.

### 5.5 Safety layer
- **Tripwire**: for each blocker rule, if any of its `keywords` appears in the message (case-insensitive, word
  boundary) and a field of that rule is not stated, the agent card shows **"Unclear: <field> — mentioned but not
  confirmed"** (amber), and the field is marked `unclear`.
- **Verdict cap** (code), two levels:
  - Any blocker field `unclear` (mentioned, not confirmed) → verdict cannot be better than conditional:
    "Proceed only after confirming: <fields>".
  - Any blocker field not stated and not mentioned → verdict may proceed on stated facts but must carry
    "Not checked (not in the brief): <fields>" in the verdict panel. Never presented as a clean approve.
  - A fired blocker always results in a blocking verdict.
- **Keywords must be specific** to the fact (e.g. licence/license/provisioned; SLA/service level). Generic words that
  appear in most briefs of this domain (supplier, contract, spend, cost) are not allowed as tripwire keywords.

### 5.6 Orchestration (`orchestrator/`)
- Delete `route_node`, `_llm_route`, `RoutingDecision`, `_sanitize_extracted_facts`, routing exceptions,
  `_route_selector`, conditional edges.
- Graph: `START → all agents in parallel → reconcile`. Each agent node does extract (free text only) → check →
  narrate (if triggered) internally, and streams its own events. Two supersteps.
- State: remove `routed_agents`, `skipped_agents`, `routing_reasoning`; add
  `checks: Annotated[dict[agent_id, Check], merge_dicts]` where
  `Check = {triggered: bool, stance: str|None, fired: [rule_id...], unchecked: [field...], unclear: [field...],
  evidence: {field: [quotes]}, provenance: {field: "seeded"|"extracted"}}`.
- Reconcile: `positions` = triggered agents only. `_enforce_blocker_policy` kept. Verdict cap applied in code.
  If no agent triggered: verdict "No rule triggered on stated facts" + list of couldn't-check/unclear fields.
- CoS LLM writes wording only (risks, why the brief is a challenge, conflicts, trade-off). Persona affects wording only.
  If the LLM output contradicts the code-set direction, code direction wins and the wording is regenerated or
  replaced with the deterministic template.
- Narration (`narrate()`) only for triggered agents; cannot change stance (existing guarantee kept).
- Model unavailable: seeds run fully (no extraction needed; deterministic summary template); free text → all
  fields not stated → no rule fires → verdict lists what couldn't be checked. No crash.

### 5.7 API (`api/app.py`)
- SSE: one `check` event per agent, streamed as each completes (no buffering), then `position` events for triggered
  agents, then `conflict`, then `reconciliation`. No `route` event anywhere.
- `/trigger/webhook` uses the same pipeline. Audit ledger entry records the checks table; hash chain unchanged.
- `_match_agents` may remain for ledger metadata only; no user-visible text may name a subset of agents as selected.

### 5.8 Frontend (`frontend/index.html`)
- Step 1 label: **"Council checks its rules"**. Pipeline rail shows all agents always.
- Each agent has a fixed manifest-order slot regardless of event arrival order.
- Triggered card: stance badge, fired rule descriptions, evidence quotes (or "seeded").
- Not-triggered card: if every rule was checked → "All rules checked — none tripped" (the old "Yes, compliant"
  information, preserved); otherwise "No rule triggered" plus "Couldn't check: …".
- Unclear: amber line "Unclear: … — mentioned but not confirmed".
- Never use the words "skipped" or "no impact" for a not-triggered agent.
- Dashboard simulate-email text: "convening the full council" (no subset named).
- Council tab: thresholds editable; blocker rules shown read-only with a "system-governed" label.
- History view renders old entries (pre-P3.6) without error.

## 6. Test plan (all mandatory; new behaviour gets a test that fails before and passes after)

### 6.1 Backend — rules engine (`tests/test_rules_engine.py`, new)
- Each operator and and/or/not returns correct result.
- Names resolve facts → derived → config thresholds; unknown name rejected at load.
- Call, attribute, subscript, lambda, import, dunder names → rejected at load, never executed.
- Rule with an unstated field does not fire, does not error, and reports the field as unchecked.
- Derived value with any unstated input is itself unstated.
- Most-severe stance selection across multiple fired rules.

### 6.2 Backend — configs & registry (`tests/test_registry.py`, rewrite)
- All shipped configs validate.
- Invalid rule expression → readable error at load and via config-save endpoint.
- Blocker rule without `keywords` → rejected.
- Save endpoint cannot add, remove or modify a blocker rule; threshold edit accepted and reflected in the next run.

### 6.3 Backend — migration / regression (`tests/test_golden_regression.py`, new; golden files committed first)
- Seed golden: every agent stance + driving constraint matches baseline.
- Per agent: new rules match old `evaluate()` on every golden complete fact set (while oracle exists), then match
  the stored golden outputs permanently after oracle deletion.
- Any approved difference is listed in `docs/P3.6-migration-diffs.md`; test reads the file and fails on any
  unlisted difference.
- Threshold edge cases (at / just below / just above) covered for every threshold.

### 6.4 Backend — extraction (`tests/test_extraction.py`, new; model mocked)
- Prompt contains only that agent's fields; contains no "estimate" wording; contains no persona text.
- temperature=0 passed; whole message present (assert final paragraph of a long fixture is in the prompt).
- Over-context message → clear error, no call made, no truncation.
- Null values stay not stated; no defaults substituted.
- Evidence quote not in message → value discarded. Empty evidence → discarded. Paraphrase → discarded.
  Whitespace/line-break differences → verifies.
- Cross-paragraph fact (date para 2, licence para 17) accepted with both quotes.
- Wrong type / out-of-schema key → discarded; run continues.
- Seed run → extraction not called (call count 0).
- One agent's extraction raising → that agent's fields not stated; other agents unaffected; run completes.

### 6.5 Backend — safety layer (`tests/test_safety_layer.py`, new)
- Keyword present + blocker field not stated → `unclear`; card data carries the unclear field.
- Keyword absent + field not stated → `unchecked` (not unclear).
- Keyword present + field stated with evidence → neither unclear nor unchecked; rule evaluated normally.
- Any unclear/unchecked blocker field → verdict never unconditional approve.
- Fired blocker → verdict blocking, regardless of other agents' yes stances and regardless of LLM wording.

### 6.6 Backend — orchestration / interface (rewrite: `test_chief_of_staff.py`, `test_graph_integration.py`,
`test_routing_resilience.py`, `test_profile_history_routing.py`, `test_termination.py`, `test_state.py`)
- **No routing**: every registered agent (including one added via manifest in the test) produces a `check` on every run.
- No `route_node`, `_llm_route`, `RoutingDecision` importable (assert removed).
- **Bug regression**: supplier_milestone seed → Operations triggered with licence blocker → verdict blocking.
  Repeat with an LLM stub returning the old "skip Operations" routing payload anywhere it could be consumed → no effect.
- Model unavailable: seed → full checks + deterministic summary; free text → no rule fires → verdict lists unchecked fields.
- No agent triggered → "No rule triggered on stated facts" verdict with unchecked/unclear list.
- CoS LLM output contradicting code direction (e.g. "approve" with a fired blocker) → code direction shown.
- Adversarial persona ("ignore Operations", "never block") → identical checks, stances and verdict direction to neutral persona.
- Narration cannot change a stance (kept).
- Termination bound holds with N agents.
- Each deleted routing test named in the commit message with reason "tests removed behaviour (LLM routing)".

### 6.7 Backend — API & audit (`test_api.py`, `test_trigger_audit.py`, `test_appdata_and_status.py` extended)
- SSE emits exactly one `check` per agent with fields: triggered, stance, fired, unchecked, unclear, evidence, provenance.
- No `route` event emitted.
- `conflict` and `reconciliation` emitted after all checks.
- Webhook run uses the same pipeline; ledger entry includes checks; hash chain verifies; tamper still detected.
- Pre-P3.6 history entries load and render data without error.

### 6.8 Frontend (`tests/test_frontend_e2e.py` extended)

## Implementation record (deviations and agreed changes)

- **§5.6 topology** -- as revised: one fan-out superstep, each agent does extract -> check -> narrate
  internally; `MAX_PRIOR_STEPS` stays 1. `step_count` needed a `max` reducer (LangGraph's default
  channel rejects concurrent writes even of equal values).
- **§5.3.4 equivalence** -- implemented as written; zero differences on all four agents, so
  `docs/P3.6-migration-diffs.md` records none, plus one Delivery rule-design bug fixed before commit.
- **Owner changes 1-6 (approved)**: tripwire keywords specific to the fact; two-level verdict cap;
  "All rules checked -- none tripped" card; PMO `portfolio_contention` has no rule and is appended
  reasoning context (confirmed by the zero-diff golden run).
- **Name precedence (§5.1)** -- first built with config winning on a collision (merge order was
  backwards); corrected to facts > derived > config via `ConfigurableAgent._rule_env()`, and
  `validate_rules()` now rejects any config scalar (or derived value) whose name matches a facts field at
  config load, so a collision cannot exist to be resolved either way. Tests: `test_registry.py`.
- **Verdict panel wording (owner-directed, after review)** -- the §5.5 texts "Proceed only after confirming: <fields>" and "Not checked (not in the brief): <fields>" no longer sit inside the recommendation. The headline is the recommendation only ("Proceed only after confirming the blocker-related facts listed below."); the blocker-related facts are in a separate block headed "Could stop this -- not stated in the brief", by human label, grouped by agent (max six, then "+N more", largest group first), leading with a "Confirm first" line when a blocker fact is unclear; non-blocker unchecked facts are collapsed into one sentence naming the agents ("... also needed facts the brief doesn't state -- see their cards") and stay listed on the agent cards. UI only; the payload still carries every item. The weaker (not-mentioned) level therefore no longer changes the headline at all -- it is disclosed by the block, which is always shown. Direction is unchanged.
- **Extensions beyond the literal text** -- (a) `derive()` per agent supplies derived values,
  including config-only ones (Finance's hard-breach line) and flattened dict facts (PMO), since the
  evaluator has no arithmetic/subscript; (b) the verdict cap also applies when no agent triggered
  (found by an end-to-end test); (c) a webhook run appends a second `council_checks` ledger entry
  after the trigger entry (the trigger is still recorded first); (d) `/council/retest` is kept, adapted
  to `check()`, returning `stance: null, triggered: false` for the all-clear case; (e) `unclear` is a
  subset of `unchecked` (both list it), and `Check` gained `blocker_not_mentioned` to carry the weaker
  cap level.
- **Test process note** -- `rules.py`, `base.py`/`evidence.py` and the safety-layer tests were written
  *with or before* their implementations landed in the same working session rather than strictly
  failing first; the orchestration, golden-regression and registry tests were confirmed failing before
  the migrations that made them pass.
- **Not done by the tool (owner)** -- §8.6 a-g, incl. the live determinism run and the extraction
  eval; README Limitations hit rate is a placeholder.
