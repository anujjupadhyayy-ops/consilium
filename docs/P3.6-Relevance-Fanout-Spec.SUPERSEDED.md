# P3.6 — Relevance fan-out (replaces LLM routing)

## Why
A single LLM routing call decided which agents were heard. When it skipped an agent, that agent's
`evaluate()` never ran, so its code-authoritative blocker could not fire. Observed: the
`supplier_milestone` seed (Operations `licence_provisioned_for_new_date: False`) returned
"Approve, conditional on Gate 2" on a run where Operations was skipped, and "Decline" on others.
An LLM held a veto over a code-enforced rule. That contradicts the core design claim.

## Principle
Every agent receives every decision. Each agent decides its own relevance from its own config
rules, in code. The Chief of Staff no longer routes; it adjudicates what comes back.

## Flow
message -> fan-out to ALL agents (parallel)
  each agent: facts (seed-supplied, else own narrow LLM extraction)
              -> relevance rules (code) -> evaluate() (code)
-> Chief of Staff: blocker policy -> conflict -> reconciliation (LLM wording, code-enforced policy)

## Agent outcomes (exactly three)
| outcome        | condition                                                        | shown reason                          |
|----------------|------------------------------------------------------------------|---------------------------------------|
| engaged        | stated blocker found, OR relevance rules pass and stance produced | stance + driving constraint + evidence |
| not_applicable | fields referenced by `applies_if` are stated; rules evaluate false | the failed rule, human-readable       |
| cannot_assess  | a field needed for the relevance or stance decision is not stated  | which fields were not stated          |

Blocker = a stance meaning "stop", backed by stated evidence. cannot_assess = "unknown".
Missing information NEVER produces a blocker, and a stated blocker is NEVER cancelled by missing information.
`cannot_assess` must never be rendered as "skipped" or "no impact".

### Assessment order (per agent, in code)
1. Blocker check. For each declared blocker condition: if every field that condition needs is stated
   (with verified evidence, or seeded) and it triggers -> `engaged`, stance `blocker`. Other missing fields are irrelevant.
2. Relevance. If every field referenced by `applies_if` is stated and the rules evaluate false -> `not_applicable`.
   (Only the applies_if fields are needed for this; required_facts are not.)
3. Required facts. If any `required_facts` field is not stated -> `cannot_assess` (list the fields).
4. Otherwise -> `engaged`: run evaluate() + narrate().

### Blocker conditions: one source of truth
- Blocker conditions are declared per agent (`blocker_conditions: [{fields, rule}]`). `evaluate()` must derive its
  blocker stance from the same declared conditions (call the shared checker), not from separate inline logic.
- Thresholds referenced by blocker rules stay editable in the Council UI; the conditions list itself is
  system-governed (not addable/removable via the UI), so a guardrail cannot be deleted through config.
- Test: for every agent and a matrix of full fact sets, evaluate() returns blocker iff at least one declared condition fires.

### Seeded facts
Seed facts count as stated with no extraction; the UI labels them "seeded" rather than showing empty evidence.

### No defaults, ever
Facts models must represent "not stated" explicitly (None). `evaluate()` must never run on a
schema default. A stance is computed only from stated fields; blocker conditions must declare
which fields they need so step 1 can be checked independently.

## Config change
Each `backend/agents/configs/*.json` gains `applies_if` (list of rule expressions over that agent's
facts fields) and `required_facts` (field names). Validated in `registry.py` like existing fields.
Rules are evaluated by a small safe evaluator in code (no `eval`).

## Extraction
- Seeds bypass extraction entirely (their facts are authored and treated as stated).
- Free text: one LLM call per agent, in parallel, that agent's facts schema only, temperature=0.
- The WHOLE message is given to every agent. Never chunk. If the message exceeds the model's context,
  the run fails with a clear error rather than truncating.
- Instruct the model to return null for anything not stated. REMOVE the current "make a reasonable
  illustrative estimate" instruction -- invented figures are fabrication and defeat `cannot_assess`.
- Every extracted value must include `evidence`: one or more verbatim quotes from the message, which may
  come from different paragraphs. Code verifies each quote is a substring of the message after whitespace
  normalisation. A value with missing or unverifiable evidence is discarded and the field counts as not stated.
- Relationships across paragraphs (e.g. a date in para 2 and a licence renewal in para 17) are the
  extractor's job; if it can't establish one, the field is null and the outcome is `cannot_assess`.
- Evidence quotes are carried into the assessment trace event and shown in the UI.

## Persona / user guidance
`_persona()` previously shaped the routing prompt. It may now shape narration and reconciliation WORDING
only. It must never reach extraction, relevance, blocker checks or stances.

## Streaming
Stream each agent's assessment event as it completes (no buffering). The frontend renders each into its
fixed manifest-order slot. Order is a display rule, not an arrival rule.

## Webhook / dashboard trigger
`_match_agents` keyword matching may stay for the audit ledger, but no user-visible text may imply a subset
of agents was selected (e.g. "convening Delivery, PMO..."). The dashboard says the full council was convened.

## What changes
- `orchestrator/chief_of_staff.py`: delete `route_node`/`_llm_route` routing role; add `assess_node` fan-out.
  Keep `_enforce_blocker_policy`, grounding gate (abstain if zero agents engaged on real facts).
- `orchestrator/graph.py`: route -> fan-out to all agents; remove `_route_selector` conditional edges.
- `orchestrator/state.py`: `routed_agents`/`skipped_agents` -> `assessments: {agent_id: {outcome, reason, missing}}`.
- `agents/base*.py`: `extract_facts()`, `assess_relevance()`; `narrate()` only for engaged.
- `api/app.py` trace events: `assessment` kind replaces `route`.
- `frontend/index.html` step 1: "Council assesses relevance"; three badge types with reasons and evidence quotes;
  dashboard simulate-email text no longer names a subset of agents.
- Docs: see "Documentation updates" below.

## Test plan (mandatory — every layer that changes gets tests)
Rule: new behaviour ships with a test that fails before the change and passes after. No layer is
"covered by integration". Each file below is new unless marked (rewrite).

### Backend — rule evaluator (`tests/test_relevance_rules.py`)
- Each operator (>, >=, <, <=, ==, !=, and/or, boolean fields) returns the correct result.
- Unknown field, malformed expression, attribute access / function call / import attempt -> rejected, never executed.
- Null field in a rule -> treated as missing (feeds cannot_assess), not as 0/False.

### Backend — config & registry (`tests/test_registry.py` rewrite)
- `applies_if` and `required_facts` validated: fields must exist in that agent's facts schema; bounds on list length/string size.
- Invalid rule rejected with a readable error at load AND via the Council UI edit endpoint.
- Every shipped config passes validation.

### Backend — agent assessment (`tests/test_agent_assessment.py`, plus each `test_agent_*.py` extended)
- Per agent: engaged / not_applicable / cannot_assess each reachable with a fixture.
- Blocker overrides not_applicable.
- cannot_assess lists the exact missing fields; not_applicable names the failed rule.
- narrate() called only for engaged (mock call count).
- not_applicable reachable with only applies_if fields stated (required_facts missing).
- Council UI cannot add/remove blocker conditions; threshold edits are reflected in the blocker check on the next run.
- evaluate() blocker iff a declared blocker condition fires (matrix test, every agent).
- Stated blocker + unrelated missing fields -> engaged / blocker, never cannot_assess (Operations: licence=False, capacity missing).
- Missing facts never produce a blocker stance (every agent, every blocker condition, fields absent).
- No stance is ever computed from a schema default (facts model with defaults removed/None; assert evaluate() not called when a needed field is None).

### Backend — extraction (`tests/test_extraction.py`)
- A fact needing two separate paragraphs (date in one, licence in another) is extracted with both quotes as evidence.
- A value whose evidence quote is not in the message -> discarded, field treated as not stated.
- A value with no evidence -> discarded.
- Whitespace/line-break differences between quote and message still verify; paraphrased quotes do not.
- Whole message passed to every agent (assert prompt contains the final paragraph of a long fixture).
- Message over context limit -> clear error, no truncation.
- Prompt contains only that agent's schema; contains no "estimate" instruction (assert on prompt text).
- Model returns nulls -> no defaults substituted -> cannot_assess.
- Model returns out-of-schema keys / wrong types -> dropped, agent -> cannot_assess, run continues.
- Seed run -> extraction never called (mock call count = 0).
- temperature=0 passed.

### Backend — orchestration / "routing" (`test_chief_of_staff.py`, `test_graph_integration.py`, `test_routing_resilience.py`, `test_profile_history_routing.py` — rewrite)
- Graph fans out to ALL registered agents every run, including agents added via manifest.
- One agent's extraction raising -> that agent cannot_assess; others unaffected; run completes.
- Bug regression: supplier_milestone seed -> Operations engaged with licence blocker -> verdict honours blocker. Include a stub reproducing the old skip condition.
- Grounding gate: zero engaged agents -> abstain.
- Model unavailable: seed -> full outcomes; free text -> all cannot_assess -> abstain; no crash.
- Termination bound still holds with N agents (`test_termination.py` extended).
- Persona / history / profile guidance can no longer suppress an agent (rewrite of routing-by-profile tests; state reason).
- Adversarial persona ("ignore Operations", "never block") -> identical outcomes table and stances to neutral persona.
- Persona text appears in narration/reconciliation prompts only; absent from extraction prompts (assert on prompt text).

### Backend — API (`test_api.py`, `test_trigger_audit.py` extended)
- SSE stream emits one `assessment` event per agent with outcome, reason, missing, evidence; no `route` event remains.
- Assessment events stream as each completes (not buffered); conflict and reconciliation come after all assessments/positions.
- `/trigger/webhook` runs use the same pipeline; audit ledger entry records the assessments table; hash chain still verifies.
- Stored history (`test_appdata_and_status.py`) loads old runs without crashing (old `routed_agents` shape) or migration is explicit and tested.
