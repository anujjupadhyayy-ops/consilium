# P3.5 — FINAL handover: make the backend real, wire it into the locked UI

Read CLAUDE.md, docs/00 — Build Brief.md, docs/P2-Agent-Logic-Spec.md, docs/DESIGN-TOKENS.md first.

The frontend is LOCKED and provided at `frontend/index.html` (Consilium's five-surface UI — Dashboard,
Decision desk, History, Council, Settings-behind-avatar; navy dark theme; Chief of Staff throughout).
DO NOT redesign it. Your job is to make the backend genuinely reason and wire it into THIS interface.
The current UI runs on scripted data; replace that data with live backend calls of the same shape.

## 1. Agents genuinely reason (not rule-evaluation)
- Keep each agent's deterministic hard-signal computation from its `agents/configs/*.json` — this stays
  the guardrail and the tests. Add an LLM step: the agent's config (lens + rules) becomes its system
  prompt; the LLM reasons over the input facts + the computed signals to produce reasoning,
  driving_constraint and lead_figure. Stance must stay consistent with the hard signal (a computed
  breach can't return "yes"). Structured output. Use model/client.py (OpenAI-compatible; env-driven).

## 2. Routing is a real LLM decision
- Replace the unconditional fan-out. The master (now the "Chief of Staff") reads the input and selects
  which specialists are relevant, with a reason each and explicit skips. Conditional edges / Send.
  Keep termination bounded (route → parallel specialists → reconcile; no loops).

## 3. Reconcile is genuine deliberation
- The Chief of Staff LLM weighs the conflicting positions, names the trade-off from the real
  constraints, applies the disclosed operational-blocker-wins policy, and always outputs
  recommendation + assumptions + not_considered.

## 4. Stream into the provided UI
- Add a FastAPI SSE endpoint that emits the trace events (route / dispatch / position / conflict /
  reconciliation) progressively. Wire `frontend/index.html`'s Decision-desk run to consume the stream
  and render the existing steps (routing card, parallel agent lanes, conflict, verdict) from live events.
  Match the event field names the UI already uses.

## 5. Wire the interactive surfaces the UI already exposes
- Council re-tests: the Finance thresholds and the Operations licence toggle currently recompute in JS.
  Back them with a real endpoint that re-evaluates the agent config against the scenario and returns the
  recomputed stance (this is the live proof that rules are data).
- Settings: model config (provider/base_url/model/key) persists to server-side env; the "Save & test"
  does a real connectivity check. Gmail/Outlook stay OAuth read-only STUBS (roadmap) — do not build
  full OAuth; keep the consent-handshake simulation.
- Trigger: an endpoint that takes a (simulated) inbound email, has the Chief of Staff match trigger
  keywords/senders from agent config, and convenes the council. The Dashboard "Simulate inbound email"
  calls it. Real inbox = OAuth read-only, single-tenant, roadmap.

## 6. Naming, guardrails, tests, ship
- Rename Master Orchestrator → Chief of Staff in code, trace and docstrings to match the UI.
- Recommend-only; bounded termination; LangSmith optional (skip if no key).
- Keep deterministic + config-swap tests (mock the LLM); add: router selects a subset, stance never
  contradicts the hard signal, reconcile applies the blocker policy.
- Serve the frontend from the backend (or document running both). Update README with a "run it in 5
  minutes with your own model key" fork guide.
- Small commits; push if `gh auth status` is authed; append a dated P3.5 milestone to the Working
  Folder's memory/evolution-log.md.

## Acceptance bar
Type a free-text back-office dilemma (not a seed) → the Chief of Staff picks who to involve → the chosen
agents reason live and in parallel, streamed into the provided UI → they genuinely disagree → the Chief
of Staff deliberates and adjudicates. Editing a rule in Council changes the real outcome. If it still
behaves like scripted lenses, it has failed.

## After P3.5
P4 = deploy (rate-limited public demo on a cheap OSS model) + record the 90-sec video + the "how it was
built" page. Those are the three showcase deliverables.
